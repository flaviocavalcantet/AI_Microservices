ARCHITECTURE AT A GLANCE:
─────────────────────────────────────────────────────────────────────────────

Request Flow:
  Client Request
       ↓
  Authorization Header: Bearer <token>
       ↓
  Middleware: Extract & validate JWT
       ↓
  AuthContext injected into g
       ↓
  Route Decorator: Check role/permission
       ↓
  Route Handler: Execute business logic
       ↓
  Response: Success or Error


Authorization Layers:
  Layer 1: JWT signature validation (cryptographic)
  Layer 2: Token claims validation (issuer, audience, expiration)
  Layer 3: Role-based access (RBAC)
  Layer 4: Resource ownership (user owns resource)
  Layer 5: Custom policies (business logic)


Error Handling:
  401 Unauthorized    → No token or invalid token
  403 Forbidden       → Authenticated but lacking permissions
  400 Bad Request     → Malformed header
  500 Internal Error  → Authorization logic error (should not happen)


ROLES EXPLAINED:
─────────────────────────────────────────────────────────────────────────────

ADMIN
  - Full system access
  - Can bypass ownership checks
  - Can perform all operations
  - Use: System administrators

USER
  - Standard authenticated users
  - Can create/read/update own resources
  - Cannot delete resources
  - Cannot access admin endpoints
  - Use: Regular users of the platform

WORKER
  - Service-to-service authentication
  - Limited to specific operations
  - Cannot access user-facing endpoints
  - Cannot perform admin operations
  - Use: Services calling other services
  - Examples: api-service → ai-worker
